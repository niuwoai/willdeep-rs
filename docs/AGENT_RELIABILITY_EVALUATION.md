# Agent 可靠性任务评测

入口：`ruby scripts/agent_reliability_eval.rb`。该命令使用指定 CLI 二进制及当前配置中的真实 Provider，可能产生模型调用费用。样本位于独立临时 Git 仓库；不会使用产品源码作为待修改样本。

先执行不联网预检：

```sh
ruby scripts/agent_reliability_eval.rb --prepare-only
```

预检必须证明每个缺陷样本测试失败、已知正确实现测试通过。它生成 JSON/Markdown 报告，但执行数为零，不计为 Agent 任务成功。

真实评测示例：

```sh
cargo build -p willdeep --bin willdeep --offline
ruby scripts/agent_reliability_eval.rb --timeout 180 --max-turns 6
```

可指定 `--binary`、`--config`、`--model`、`--out`。当前进程监控依赖 Unix 进程组，评测驱动在 macOS/Linux 使用；这不代表 Windows Runtime 已完成动态验收。

首批样本：

- `dirty_files`：修复求和边界错误，测试必须通过，验收测试、Cargo.toml 和既有未提交笔记不得变化，CLI 必须报告完成并返回 0。
- `repeated_failure`：保持文件不变，检查已知失败的测试；CLI 必须返回部分结果及退出码 5。此项衡量失败处理是否符合契约，不计作代码修复能力。
- `subtask_integration`：先派当前公开职责中的前台只读 reviewer 诊断缺陷，再由主 Agent 集成修复并验证。除独立测试通过及受保护文件不变外，CLI NDJSON 必须包含同一子 Agent 的有序 started/completed 生命周期，且其终态为 completed。仅有主任务修复、启动事件、部分结果或正文声称派工均不通过。
- `compression_constraints`：固定会话在首条用户消息保存修复要求与文件约束；通过现有 Web 桥接 CLI 的 `/compress` 实际压缩，再续跑同一会话。压缩完成事件、持久代次、消息数减少和原始约束逐字保留均必须成立，最终修复仍接受独立测试和文件保护验收。两个阶段共用超时预算；不修改用户配置。
- `interruption_recovery`：要求先单独执行固定追加命令；只有标记恰好一行、对应工具结果已持久化、检查点仍在运行且无待返回调用时才注入中断。终止后重新确认该边界，再恢复同一会话完成修复。最终要求标记仍为一行、原调用只出现一次、检查点完成，以及独立测试和受保护文件验收通过。未核实中断的场景按失败记录，不加入恢复率分母。

报告中的完成率是这些可靠性场景的外部验收通过率；不是通用编程能力评分。误报完成率按全部实际执行场景计算。Token 取本次隔离状态目录的检查点；没有用量时保留 null，不填零。无人值守运行不会自动回答审批问题，人工介入数固定为实际发生的零次。

外部验收会重新创建独立目录，仅复制待修的 `src/lib.rs`，使用固定清单和验收测试，最长执行 30 秒。工作区内测试被删除、Cargo 配置被篡改或新增其他文件，都不能因此获得成功；除允许修改的实现以及构建产物和 Git 内部数据外，样本文件按内容及权限比较。用量只接受 CLI 返回的那个会话 ID，异常或缺失计数保留 null。

报告不包含配置内容、凭据或模型原始文本。原始输出留在私有临时状态目录，最终 JSON/Markdown 默认写到 `target/agent-reliability-eval`，并记录实际二进制 SHA-256。

评测进程由私有 Ruby 监督器持有进程组：命令退出码通过独立管道回传，监督器在组清理前不回收，避免超时与等待线程之间的 PID 复用竞态。正常完成、超时和注入中断均先清理组；驱动意外退出时存活管道关闭也触发清理。该保证针对同一 Unix 进程组，不声称能清理主动建立新会话/进程组的程序。

子任务场景只从结构化事件读取生命周期，不把工具输出或模型正文解析为事件；NDJSON 缺少完整最终记录、存在损坏行或被截断时不能报告完成。该样本验证诊断型只读子任务的完成与最终修复，不覆盖写入型子任务的工作树合并。

手工压缩调用的 Token 用量尚未由 CLI 完整暴露，因此压缩场景的 Token 指标保留 null，不能仅用后续修复的用量冒充总量。该场景覆盖显式压缩，不代表自动窗口阈值策略的评测。

恢复率仅统计已核实注入中断的运行；没有此类运行时保留 null。恢复场景的中断前在途请求用量无法完整取得，Token 指标也保留 null。该样本检查固定写入后的恢复，不代表任意命令副作用、工具执行中断或写入型子任务恢复均已验收。

用户已授权 DeepSeek 调用及费用。rc58 使用 deepseek-v4-flash 完成五类真实场景，5/5 通过，误报完成率 0%，已核实中断恢复 1/1；报告见 [真实评测报告](evaluations/agent-reliability-rc58.md) 和对应 JSON。评测将主任务与辅助任务固定为同一 DeepSeek 模型，临时配置不进入仓库。上述结果仅代表五个固定可靠性样本；不联网预检仍不算实际执行。

Markdown 与 JSON 同步展示汇总完成率、误报率、恢复率，以及逐场景耗时、输入/输出 Token、人工介入次数。未执行或缺失完整证据的指标显示“未取得”；实际测得的零值仍显示 0。
