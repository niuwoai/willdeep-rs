# 显式任务验收检查

在任务使用的配置文件中增加：

```toml
[agent]
verification_commands = ["cargo test -p willdeep-core", "cargo test -p willdeep"]
```

这是可选设置，默认没有显式检查清单。可通过已有的 `--config` 参数选择任务专用配置；保留该配置原有 Provider 等设置，不要把凭据复制到版本库。

## 完成判定

- Agent 从第一轮开始收到清单，但配置不自动启动命令，也不授予额外权限；执行仍经过 `run_command`、审批和沙箱。
- 每个配置命令都必须在最终 Git 工作区快照上通过；无关测试通过、只运行部分清单、代码没有变化，都不能替代剩余检查。
- 验证命令成功结束后复核起止快照；执行中快照变化或结束时不可读，退出码 0 仍会被标记为验证证据失效，必须在稳定快照上重新检查。
- 修改代码后，旧快照上的通过记录不能满足显式清单。无法完成验证时保留部分结果，不报告已验证完成。
- 显式清单要求可读取的 Git 快照；普通非 Git 问答在未配置清单时仍可正常使用。
- 未完成任务把清单保存到执行检查点；恢复时合并原清单，删除配置项不能取消原要求。新增要求可以加强清单，合并后最多 32 项。
- 已完成任务的检查点不会向新的执行器注入旧清单。需要变更尚未完成任务的验收范围时，开启新的独立会话；当前实现没有由模型删除验收项的入口。

## 输入边界

每条命令最多 2048 字节，只接受运行器可识别的测试/验证命令。拒绝敏感参数、管道、条件串联、未引用的换行及 `--list`、`--no-run` 等已识别的非执行选项。不同命令按去除首尾空白后的完整字符串匹配，不推断两个不同命令是否等价，也不保证识别所有测试框架的特殊选项。

该清单提供命令级验收要求，不自动证明全部自然语言需求；测试覆盖范围仍由调用方定义。真实任务评测覆盖及完整 Runtime 派工恢复见 `AGENT_RELIABILITY_WORK.md`。
